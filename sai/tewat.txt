2. What IDM can and can't do
Purpose: ✅ The IDM Test Data Management (TDM) tool lets test teams create their own test identities: Workday, Fieldglass and GSM Test (Magenta AD) users. SailPoint then provisions them into Active Directory and Azure AD (Entra ID). Source: IDM Test Data Management Tool.

Production or non-production only:

✅ The documented tool URLs exist only for non-production environments: QLAB01/02/03/06/07 and PLAB01.

✅ Passwords are reset in the "Non Production" section of the OLIO tool, against the test domain GSMTEST.ORG.

✅ The Process Creating New Users via IDM User Utility Tool page calls it the "IDM NPE User Creation Tool".

⚠️ Whether IDM can create production PerfUsers remains unverified. No page confirms or rules it out. Every documented path is non-production, which matches what you heard about Anderson's access.

Step-by-step guide: ✅ Yes, for non-production only, on the IDM Test Data Management Tool page:

Create the user using the URL for your environment.

Retrieve the Personnel Number under the Provisioning Status tab.

Confirm the user exists in AD (allow about 2 hours for SailPoint).

Reset the password in OLIO.

The official guide is the IDM SharePoint page.

Bulk creation: ✅ Supported in non-production only. You upload an Excel template of up to 50 users per batch, with or without extension attributes, and accounts are valid for 6 months.

Rules that apply to you (same page):

IDM does not supply test data. The test team provides valid attributes.

Test accounts and passwords are owned and managed by the test team, not IDM.

Support requests need a Jira ticket: project "Operational Excellence", R2D2 team "IDM-NPE-SUPPORT", component "IDM - NPE Support". The page says IDM doesn't respond to email or Teams. Problems with the tool itself go to ServiceNow, assigned to "ISAM Identity Security".

Anderson Dorvil's documented role: ✅ He is named as the IDM contact only in non-production contexts:

IDM Sailpoint Login Creation Updated

Expert Assist / Atlas IDs for QLABs

Test - Atlas NPE, which includes syncing new users to the iHub database

If IDM can't create production users: ⚠️ No alternative is documented. 🔎 The likely owner is IAM / ISAM Identity Security, through ServiceNow/Compass.

🔎 A likely blocker:

TIP checks each user's access to semantic models through Fabric. Access comes from the TMobileUSA Entra ID tenant, Provisionator security groups and row-level security.

Users created in GSMTEST.ORG probably won't exist in that production tenant, so they probably can't sign in to production TIP.

Sources: Enterprise Semantic Layer (Semantic) Overview and TIP WebApp.

5. Do you need an ADM account?
✅ An ADM account is a privileged account you request through Compass – Request an Elevated Account. It needs manager approval, a TESS password reset and security-key MFA. The page says its purpose is signing in to the Azure Portal instead of using your NTID. Source: ADM Account Creation.

Required for IDM, LRE or the CIM page? ✅ No documentation lists it as a requirement. LRE sign-in uses your NTID through SSO.

Does it give you PerfUsers? 🔎 No. It's your personal privileged identity, not a load-test user, and nothing says it can create users.

Other roles needed:

LRE: access to the right domain and project, plus a separate execution permission.

TIP: Provisionator, model and TIP security groups.

7. Using PerfUsers in LRE
Access steps ✅ (sources: Load Runner Execution [LRE] and VUGen, Performance Testing with Load Runner, FAQ - LRE/LRC):

Submit LRES - General Help / New User Access. Raise separate tickets for non-prod and prod. The CDM example uses projects xECM and xECM_PROD in domain DEVOPS. ⚠️ Those are that team's projects; confirm which LRE project TIP uses.

In My Apps, go to Add apps → Request new apps → LoadRunner Enterprise.

Submit LRES - Enable Execution. One page says this lasts a week, another says it's a daily window.

On a Mac, request [MDC access] (https://myaccess.microsoft.com/@TMobileUSA.onmicrosoft.com#/access-packages/e37fd08c-c3c1-4d5e-93f2-9102de4996c3), then install VuGen and Analysis 26.1.03 from Software Center (Set Up for New User).

Where test users are stored:

✅ T-Mobile's LRE supports VTS (Virtual Table Server) tables, and the LRE FAQ shows how scripts connect to them.

✅ VuGen can store scripts in GitLab.

⚠️ CSV/DAT parameter files are standard LoadRunner practice, but no TIP-specific setup is documented.

Without LRE portal access: 🔎 You may be able to see scripts and parameter files if they're in GitLab. VTS tables and project assets need LRE project membership.

Permissions to see existing scripts: ✅ Signing in isn't enough. You need membership of the right domain and project, granted by the project administrator. "Create Test" and execution rights are separate (FAQ).

Platform fit:

✅ LRE is meant for non-production environments and production retail/care apps. Avoid tests of 40,000 or more users on LRE because of port exhaustion.

✅ LoadRunner Cloud (LRC) is meant for large production tests of Digital apps.

🔎 TIP runs on Azure App Service, so make sure the firewall rules are in place first (Firewall Requirements).
